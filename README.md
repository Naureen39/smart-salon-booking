# GlowDesk — AI Salon & Spa Booking Platform

A production-grade SaaS for salons/spas: a polished public site, client auth,
a token-minimized text + voice booking assistant (Groq primary / Gemini
fallback LLM router with rule-based slot filling and pgvector-backed RAG for
FAQs), a scikit-learn no-show risk model driving smart reminder timing, and
an owner-facing analytics dashboard. Built entirely on free/open-source
components — see [`salon-booking-saas-dev-plan.md`](salon-booking-saas-dev-plan.md)
for the full architecture and phased build plan.

```
          │ PostgreSQL 16 +     │   │ Redis (cache,     │
          │ pgvector extension  │   │ Celery broker,    │
          │ (bookings, clients, │   │ rate limiting,    │
          │  FAQ embeddings,    │   │ session store)    │
          │  audit log)         │   └───────────────────┘
          └─────────────────────┘
```

## Stack

- **Backend:** FastAPI, SQLAlchemy 2.0 (async), Alembic, PostgreSQL 16 + pgvector, Redis, Celery
- **Frontend:** React 18 + TypeScript + Vite, Tailwind CSS, TanStack Query, Zustand, Recharts, Framer Motion
- **AI:** Groq (`openai/gpt-oss-20b`) primary LLM, Gemini Flash/Flash-Lite fallback, `BAAI/bge-small-en-v1.5` embeddings, `faster-whisper` (STT), `pyttsx3` offline TTS by default (OpenVoice V2 is a real, ready integration point — see [Known Limitations](docs/KNOWN_LIMITATIONS.md))
- **ML:** scikit-learn no-show risk scoring (gradient boosting + logistic regression companion)

## Local development

1. Copy the environment template and fill in your free-tier API keys:

   ```bash
   cp .env.example .env
   ```

2. Bring up the full stack:

   ```bash
   docker compose up --build
   ```

   This starts Postgres (with pgvector), Redis, the FastAPI backend, Celery
   worker + beat, and the Vite dev server for the frontend.

3. Apply database migrations (from the `backend` container or locally with
   `DATABASE_URL` pointed at the compose Postgres instance):

   ```bash
   cd backend
   alembic upgrade head
   ```

4. Seed some starter data (optional but recommended for a non-empty dev environment):

   ```bash
   cd backend
   python -m scripts.seed_faq
   python -m scripts.generate_synthetic_data --rows 20000 --out data/synthetic_appointments.csv
   python -m app.ml.train --data-path data/synthetic_appointments.csv
   python -m scripts.backfill_analytics --days 90
   ```

- Backend API: http://localhost:8000 (interactive docs at `/docs`, ReDoc at `/redoc` — both auto-generated by FastAPI from the route definitions, no extra work needed)
- Frontend: http://localhost:5173 (marketing site + chat widget), http://localhost:5173/admin (analytics dashboard)

## Running tests

```bash
# Backend
cd backend && pip install -r requirements-dev.txt && pytest

# Frontend
cd frontend && npm install && npm run test
```

CI (`.github/workflows/ci.yml`) runs lint + type-check + tests + a Docker build for both backend and frontend, plus dependency vulnerability scanning, on every push/PR.

## Project status

All 13 phases of the development plan are implemented and verified against real infrastructure (ephemeral Postgres/Redis, real embedding/ML models — not mocks) at every phase:

- **Phase 0–2**: scaffolding, auth/RBAC, booking engine with DB-level double-booking prevention.
- **Phase 3–6**: no-show ML pipeline, reminder engine, RAG FAQ answering, dual-LLM router with failover.
- **Phase 7–8**: conversation orchestrator (chat + voice) with a token-minimized rule-first design.
- **Phase 9–10**: admin analytics dashboard, public marketing site.
- **Phase 11–13**: security hardening, CI/CD + deployment docs, this documentation pass.

See `docs/KNOWN_LIMITATIONS.md` for what's deliberately out of scope and how to extend it.
